# Vendo Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a Rails app that serves an ACP product feed and checkout API to AI shopping agents, plus a Claude-powered buyer-agent harness that exercises it end to end.

**Architecture:** ACP controllers under `Vendo::` talk to a single `Vendo::Catalog` module, which is the only file permitted to reference ActiveRecord models. Serialization is plain Ruby objects returning Hashes. Payment sits behind a one-method processor seam with a fake default. A merchant admin gives a human something to watch while the harness shops.

**Tech Stack:** Rails 7.2.3, Ruby 3.4.9, SQLite, Minitest (Rails default), the `anthropic` gem for the harness. No jbuilder, no serializer gem, no state-machine gem, no Money gem.

## Global Constraints

- **ACP API version is `2025-09-12`.** Every checkout-session response sets the `API-Version` header to this value.
- **All monetary values are integer minor units (cents)** everywhere except the product feed, which uses the spec's `"79.99 USD"` string form.
- **The seam rule:** `app/lib/vendo/catalog.rb` is the ONLY file allowed to reference `Product`, `LineItem`, `Order`, or `CheckoutSession`. Controllers, serializers, `Totals`, and `Fulfillment` must never touch ActiveRecord. A task that breaks this rule is wrong even if its tests pass. (`app/models/` and `app/controllers/admin/` are exempt — the admin is a human UI, not part of the engine-extractable surface.)
- **Deliberate simplifications get a `ponytail:` comment at the site**, naming the ceiling and the upgrade path.
- **Every checkout-session response includes** `fulfillment_options`, `totals`, `messages`, and `links` — all four are required by the spec even when empty-ish. `payment_provider` is additionally required on create and complete.
- **Session status is computed, never stored**, except the two terminal states (`completed`, `canceled`) which live in the `terminal_status` column.
- **Spec source of truth:** `docs/superpowers/specs/2026-08-09-vendo-design.md`, reconciled against `developers.openai.com/commerce/specs/checkout` and `/specs/feed`.

## File Structure

| File | Responsibility |
|---|---|
| `config/initializers/vendo.rb` | Single-merchant config: seller identity, tax rate, shipping, links |
| `db/migrate/*` | Six tables: products, checkout_sessions, line_items, orders, idempotency_keys, api_clients |
| `app/models/*.rb` | Thin AR models. Validations only, no business logic |
| `app/lib/vendo/catalog.rb` | **The seam.** Every model access in the ACP layer routes through here |
| `app/lib/vendo/totals.rb` | Typed totals array |
| `app/lib/vendo/fulfillment.rb` | The one hardcoded shipping option |
| `app/lib/vendo/payment_processor.rb` | `FakeProcessor` + `StripeProcessor` behind one call |
| `app/lib/vendo/webhook.rb` | Fire-and-log order events |
| `app/serializers/vendo/feed_serializer.rb` | Product → feed row |
| `app/serializers/vendo/checkout_session_serializer.rb` | Session → ACP response Hash |
| `app/controllers/vendo/base_controller.rb` | Auth, idempotency, header echo, error rendering |
| `app/controllers/vendo/feed_controller.rb` | `GET /feed.json` |
| `app/controllers/vendo/checkout_sessions_controller.rb` | The five checkout endpoints |
| `app/controllers/admin/*` | Merchant admin (products CRUD, sessions, orders) |
| `harness/` | Plain Ruby buyer agent, outside `app/` so Rails does not autoload it |
| `test/integration/*` | The three integration tests |

```ruby
module Vendo
  # THE SEAM.
  #
  # This is the only file in the ACP layer permitted to reference Product,
  # CheckoutSession, LineItem, or Order. Controllers and serializers call these
  # methods and never touch ActiveRecord directly.
  #
  # It exists for one reason: at step 3 the ACP layer moves into a mountable
  # engine and the host application supplies its own Catalog. Everything above
  # the seam moves unchanged.
  #
  # ponytail: no merchant scoping — there is deliberately no Merchant model and
  # no merchant_id column. Because every query routes through here, adding
  # tenancy later is a change to this one file rather than a migration and
  # query-rewrite across five.
  module Catalog
    module_function

    def feed_items
      Product.order(:item_id)
    end

    def in_stock?(item_id, quantity)
      product = Product.find_by(item_id: item_id)
      return false if product.nil?
      product.availability == "in_stock" && product.inventory_quantity >= quantity
    end
  end
end
```

```ruby
module Vendo
  # Product -> one ACP product feed row.
  #
  # Field names here are the feed spec's, not ours: `url` not `link`, `image_url`
  # not `image_link`, `group_id` not `item_group_id`. Do not "fix" them.
  class FeedSerializer
    def initialize(product)
      @product = product
    end

    def as_json
      c = Rails.configuration.vendo
      {
        item_id: @product.item_id,
        title: @product.title,
        description: @product.description,
        brand: @product.brand,
        url: @product.url,
        image_url: @product.image_url,
        price: format_price,
        availability: @product.availability,
        condition: @product.condition,
        group_id: @product.group_id,
        is_eligible_search: true,
        is_eligible_checkout: @product.availability == "in_stock" && @product.inventory_quantity.positive?,
        seller_name: c.seller_name,
        seller_url: c.seller_url,
        seller_tos: c.seller_tos,
        seller_privacy_policy: c.seller_privacy_policy,
        target_countries: c.target_countries,
        store_country: c.store_country
      }
    end

    private

    # The feed spec wants "79.99 USD", not minor units. This is the only place
    # in the app that leaves integer cents.
    def format_price
      format("%.2f %s", @product.price_cents / 100.0, @product.currency)
    end
  end
end
```

```ruby
module Vendo
  class BaseController < ActionController::API
    before_action :authenticate_client!
    around_action :with_idempotency, only: %i[create update complete cancel]
    after_action :echo_protocol_headers

    private

    attr_reader :current_client

    def authenticate_client!
      token = request.headers["Authorization"].to_s.delete_prefix("Bearer ").strip
      @current_client = ApiClient.authenticate(token)
      return if @current_client

      render_acp_error(code: "invalid", message: "Missing or invalid API key.",
                       status: :unauthorized)
    end

    # ACP replay semantics: same key + same body replays the stored response
    # verbatim; same key + different body is an error, not a second write.
    def with_idempotency
      key = request.headers["Idempotency-Key"]
      return yield if key.blank?

      fingerprint = Digest::SHA256.hexdigest("#{request.method}:#{request.path}:#{request.raw_post}")

      if (stored = IdempotencyKey.find_by(key: key))
        if stored.request_fingerprint == fingerprint
          render json: stored.response_body, status: stored.status_code
        else
          render_acp_error(code: "request_not_idempotent",
                           message: "This Idempotency-Key was already used with a different request body.",
                           status: :conflict)
        end
        return
      end

      yield

      # Only successful writes are worth replaying; a 4xx should be retryable.
      return unless response.successful?

      IdempotencyKey.create!(key: key, request_fingerprint: fingerprint,
                             response_body: response.body, status_code: response.status)
    end

    def echo_protocol_headers
      response.headers["API-Version"] = Rails.configuration.vendo.api_version
      response.headers["Idempotency-Key"] = request.headers["Idempotency-Key"] if request.headers["Idempotency-Key"]
      response.headers["Request-Id"] = request.headers["Request-Id"] if request.headers["Request-Id"]
    end

    # ACP's top-level error shape. Per-field problems belong in the session's
    # `messages` array, not here.
    def render_acp_error(code:, message:, status:, param: nil)
      body = {type: "invalid_request", code: code, message: message}
      body[:param] = param if param
      render json: body, status: status
    end
  end
end
```

```ruby
  # ACP's `totals` is an ARRAY of typed entries, not a hash. The full enum is
  # items_base_amount, items_discount, subtotal, discount, fulfillment, tax,
  # fee, total. We emit only the four this store uses and omit the rest rather
  # than padding the response with zeros.
  module Totals
    module_function

    def build(items_base_cents:, fulfillment_cents:)
      tax = tax_cents(items_base_cents + fulfillment_cents)
      [
        {type: "items_base_amount", display_text: "Items",    amount: items_base_cents},
        {type: "fulfillment",       display_text: "Shipping", amount: fulfillment_cents},
        {type: "tax",               display_text: "Tax",      amount: tax},
        {type: "total",             display_text: "Total",    amount: items_base_cents + fulfillment_cents + tax}
      ]
    end

    # ponytail: flat rate on the whole taxable base — real tax is per
    # jurisdiction and per product category. Swap in a tax service at step 2.
    def tax_cents(base_cents)
      (base_cents * Rails.configuration.vendo.tax_rate).round
    end
  end
```

```ruby
module Vendo
  # Turns the plain Hash from Vendo::Catalog into an ACP checkout session
  # response. Deliberately knows nothing about ActiveRecord.
  #
  # Every response carries fulfillment_options, totals, messages, and links.
  # payment_provider is additionally required on create and complete.
  class CheckoutSessionSerializer
    def initialize(data)
      @data = data
    end

    def as_json(include_payment_provider: false)
      body = {
        id: @data[:public_id],
        status: @data[:status],
        currency: @data[:currency],
        line_items: @data[:line_items].map { |li| line_item(li) },
        fulfillment_options: Fulfillment.options,
        totals: Totals.build(items_base_cents: items_base_cents,
                             fulfillment_cents: Fulfillment.cents_for(@data[:fulfillment_option_id])),
        messages: @data[:messages],
        links: links
      }

      body[:buyer] = @data[:buyer] if @data[:buyer].present?
      body[:fulfillment_address] = @data[:fulfillment_address] if @data[:fulfillment_address].present?
      body[:fulfillment_option_id] = @data[:fulfillment_option_id] if @data[:fulfillment_option_id].present?
      body[:payment_provider] = payment_provider if include_payment_provider
      body[:order] = @data[:order] if @data[:order].present?
      body
    end

    private

    # ACP nests the ordered item inside the line item. The database keeps
    # product_id and quantity flat on the row; the nesting happens here.
    def line_item(li)
      {
        id: li[:public_id],
        item: {id: li[:item_id], quantity: li[:quantity]},
        base_amount: li[:base_amount],
        discount: li[:discount],
        subtotal: li[:subtotal],
        tax: li[:tax],
        total: li[:total]
      }
    end

    def items_base_cents
      @data[:line_items].sum { |li| li[:base_amount] }
    end

    def payment_provider
      {provider: "stripe", supported_payment_methods: ["card"]}
    end

    def links
      c = Rails.configuration.vendo
      [
        {type: "terms_of_use", url: c.seller_tos},
        {type: "privacy_policy", url: c.seller_privacy_policy}
      ]
    end
  end
end
```

```ruby
    # Raised when the agent references an item_id the store does not have. The
    # controller turns this into an ACP `invalid` error; a missing product is a
    # bad request, not an empty result.
    class UnknownItem < StandardError; end

    def create_session(items:, buyer: nil, fulfillment_address: nil)
      session = CheckoutSession.new(buyer: buyer, fulfillment_address: fulfillment_address,
                                    currency: Rails.configuration.vendo.currency)
      CheckoutSession.transaction do
        session.save!
        replace_line_items(session, items)
      end
      present(session.reload)
    end

    def find_session(public_id)
      session = CheckoutSession.find_by(public_id: public_id)
      session && present(session)
    end

    # Turns the record graph into the plain Hash every serializer consumes.
    # Nothing above the seam ever sees an ActiveRecord object.
    def present(session)
      line_items = session.line_items.includes(:product).order(:id).map do |li|
        {
          public_id: li.public_id,
          item_id: li.product.item_id,
          quantity: li.quantity,
          base_amount: li.base_amount,
          discount: li.discount,
          subtotal: li.subtotal,
          tax: li.tax,
          total: li.total
        }
      end

      {
        public_id: session.public_id,
        status: status_for(session, line_items),
        currency: session.currency,
        buyer: session.buyer,
        fulfillment_address: session.fulfillment_address,
        fulfillment_option_id: session.fulfillment_option_id,
        line_items: line_items,
        messages: stock_messages(line_items),
        order: order_for(session)
      }
    end

    def replace_line_items(session, items)
      session.line_items.destroy_all
      items.each do |item|
        item_id = item[:id] || item["id"]
        quantity = (item[:quantity] || item["quantity"]).to_i
        product = Product.find_by(item_id: item_id)
        raise UnknownItem, item_id.to_s if product.nil?

        base = product.price_cents * quantity
        tax = Totals.tax_cents(base)
        session.line_items.create!(product: product, quantity: quantity, base_amount: base,
                                   discount: 0, subtotal: base, tax: tax, total: base + tax)
      end
    end

    # Status is derived, never stored — except the two terminal states, which
    # are facts rather than derivations.
    def status_for(session, line_items)
      return session.terminal_status if session.terminal_status.present?

      ready = session.fulfillment_address.present? &&
              Fulfillment.valid?(session.fulfillment_option_id) &&
              line_items.all? { |li| in_stock?(li[:item_id], li[:quantity]) }

      ready ? "ready_for_payment" : "not_ready_for_payment"
    end

    # This is how the agent learns WHY a session is not ready. Without it the
    # agent sees a status flip with no explanation and cannot recover.
    def stock_messages(line_items)
      line_items.each_with_index.filter_map do |li, index|
        next if in_stock?(li[:item_id], li[:quantity])

        {
          type: "error",
          code: "out_of_stock",
          param: "$.line_items[#{index}]",
          content_type: "plain",
          content: "#{li[:item_id]} is not available in the requested quantity."
        }
      end
    end

    def order_for(session)
      order = session.order
      return nil if order.nil?

      {id: order.public_id, checkout_session_id: session.public_id,
       permalink_url: order.permalink_url}
    end
```

and this method:

```ruby
    # The whole completion runs in one transaction: re-check stock, decrement,
    # charge, write the order. A session that went stale between ready and
    # complete fails here rather than overselling.
    #
    # ponytail: no reservation — two agents can both hold a ready_for_payment
    # session for the last unit and one loses at this point. Real holds need a
    # Reservation row with a TTL and a sweeper.
    #
    # Note: `lock!` is a no-op on SQLite, which has no SELECT ... FOR UPDATE.
    # The guarantee here comes from SQLite serializing writes, plus the explicit
    # inventory re-check below. Keep the re-check even if the database changes —
    # on Postgres the `lock!` calls start doing real work and the re-check is
    # what makes them correct.
    def complete_session(public_id, payment_token:)
      session = CheckoutSession.find_by(public_id: public_id)
      return nil if session.nil?
      raise NotCancelable, public_id if session.terminal_status.present?

      order_data = nil

      CheckoutSession.transaction do
        session.lock!
        line_items = present(session)[:line_items]
        raise NotReady, public_id unless status_for(session, line_items) == "ready_for_payment"

        decrement!(session)

        amount = Totals.build(items_base_cents: line_items.sum { |li| li[:base_amount] },
                              fulfillment_cents: Fulfillment.cents_for(session.fulfillment_option_id))
                       .find { |t| t[:type] == "total" }[:amount]

        result = PaymentProcessor.charge(token: payment_token, amount_cents: amount)

        order = Order.create!(checkout_session: session, status: "created",
                              payment_reference: result[:reference])
        order.update!(permalink_url: "#{Rails.configuration.vendo.base_url}/admin/orders/#{order.public_id}")
        session.update!(terminal_status: "completed")

        order_data = {id: order.public_id, checkout_session_id: session.public_id,
                      permalink_url: order.permalink_url}
      end

      [present(session.reload), order_data]
    end

    def decrement!(session)
      session.line_items.includes(:product).each do |li|
        product = li.product.lock!
        raise NotReady, session.public_id if product.inventory_quantity < li.quantity

        product.update!(inventory_quantity: product.inventory_quantity - li.quantity)
      end
    end
```

```ruby
require "net/http"
require "json"
require "securerandom"
require "uri"

# Thin ACP client. Net::HTTP from stdlib — no Faraday, no HTTParty.
module MerchantHttp
  BASE = ENV.fetch("VENDO_BASE_URL", "http://localhost:3000")
  TOKEN = ENV.fetch("VENDO_AGENT_TOKEN", "dev-agent-token")

  module_function

  def get(path)
    request(Net::HTTP::Get, path)
  end

  def post(path, body)
    request(Net::HTTP::Post, path, body)
  end

  def request(klass, path, body = nil)
    uri = URI("#{BASE}#{path}")
    req = klass.new(uri)
    req["Authorization"] = "Bearer #{TOKEN}"
    req["Content-Type"] = "application/json"
    req["Idempotency-Key"] = SecureRandom.uuid
    req["Request-Id"] = SecureRandom.uuid
    req["API-Version"] = "2025-09-12"
    req.body = body.to_json if body

    response = Net::HTTP.start(uri.hostname, uri.port) { |http| http.request(req) }
    JSON.parse(response.body)
  rescue JSON::ParserError
    {"error" => "non-JSON response", "status" => response&.code}
  end
end
```

```ruby
class CompleteCheckoutSessionInput < Anthropic::BaseModel
  required :session_id, String, doc: "The checkout session id to complete."
end

class CompleteCheckoutSession < Anthropic::BaseTool
  doc "Complete a checkout session and pay. Only works when the session status is ready_for_payment. Returns the session with an order attached."
  input_schema CompleteCheckoutSessionInput

  def call(input)
    MerchantHttp.post("/checkout_sessions/#{input.session_id}/complete",
                      {payment_data: {token: "spt_demo_#{SecureRandom.hex(8)}", provider: "stripe"}})
  end
end
```

- [ ] **Step 4: Write the agent loop**

Create `harness/shopper.rb`:

```ruby
require_relative "tools"

module Shopper
  SYSTEM = <<~PROMPT
    You are a shopping agent buying on behalf of a human from a merchant that
    speaks the Agentic Commerce Protocol.

    Work out the flow yourself from what the API returns. The session's `status`
    and `messages` fields tell you what is still missing; read them rather than
    guessing. A session must reach `ready_for_payment` before you complete it.

    When you need a shipping address and the human has not given you one, use:
    Ada Lovelace, 1 Analytical Way, London, LDN, GB, E1 6AN.

    Tell the human what you bought and what it cost when you are done.
  PROMPT

  module_function

  def run(request)
    client = Anthropic::Client.new

    client.beta.messages.tool_runner(
      model: :"claude-opus-5",
      max_tokens: 16_000,
      system_: SYSTEM,
      output_config: {effort: "medium"},
      tools: [FetchFeed.new, CreateCheckoutSession.new,
              UpdateCheckoutSession.new, CompleteCheckoutSession.new],
      messages: [{role: "user", content: request}]
    ).each_message { |message| render(message) }
  end

  def render(message)
    Array(message.content).each do |block|
      case block.type
      when :text      then puts "\n#{block.text}"
      when :tool_use  then puts "  -> #{block.name}"
      end
    end
  end
end
```

`effort: "medium"` because shopping is not a hard reasoning task and the harness runs frequently during development. `max_tokens` is 16k rather than the design's 8k because Claude Opus 5 thinks by default and `max_tokens` caps thinking plus text together.

````markdown
# Vendo

A Rails merchant that sells to AI agents over the [Agentic Commerce
Protocol](https://developers.openai.com/commerce), plus a Claude-powered buyer
agent that shops from it.

There is no storefront. The buyer never visits a web page — an agent reads the
product feed, calls the checkout API, and pays with a delegated payment token.
The only human-facing UI is the merchant admin.

direnv allow          # or: nix develop

bin/shop "buy me a blue mug"
```

## The API

| Endpoint | Purpose |
|---|---|
| `GET /feed.json` | Product feed (unauthenticated) |
| `POST /checkout_sessions` | Create a session |
| `GET /checkout_sessions/:id` | Retrieve |
| `POST /checkout_sessions/:id` | Update address, items, fulfillment |
| `POST /checkout_sessions/:id/complete` | Pay |
| `POST /checkout_sessions/:id/cancel` | Cancel |

All checkout endpoints require `Authorization: Bearer <token>` and honour
`Idempotency-Key`.
````
